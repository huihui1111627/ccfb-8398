# 科研数据脱敏平台（medmask）

三甲医院科研处用于向合作课题组发布临床数据的脱敏与审批平台。Rust 后端 + 内置网页控制台，
单二进制运行，数据落本地 SQLite，发布包落本地文件系统。

## 快速开始

```bash
cargo run            # 启动 http://127.0.0.1:8398
cargo test           # 隐私保证的自动化测试
```

首次启动会在 `data/` 下创建数据库、主密钥和 3 个演示课题组。浏览器打开首页即可。

| 环境变量 | 默认 | 说明 |
|---|---|---|
| `MEDMASK_ADDR` | `127.0.0.1:8398` | 监听地址 |
| `MEDMASK_DATA` | `data` | 数据库 / 主密钥 / 发布包目录 |

没有真实数据也能完整走通：进入「测试数据与检出率」页生成合成病历。

## 五个功能区

1. **数据集登记**：登记来源与负责人，上传 CSV 或含多张表的 ZIP；支持预览与搜索。
2. **字段识别**：按字段名 + 取值形态自动识别姓名、身份证、手机、住址、病案号、日期、诊断等，
   并可人工校正类型（校正会写入审计）。
3. **脱敏策略**：分别配置直接标识、自由文本内标识、日期平移、准标识泛化、k 值与风险阈值。
4. **风险评估**：全量试跑，检查 k 匿名、再识别风险、起诉风险、残留标识与统计量偏差；
   不通过则状态为「风险未通过」，无法进入审批。
5. **发布审批**：审批通过后重新按策略快照生成发布包（CSV + 清单 + 风险/质量报告 + 策略快照），
   并记录审批人与发布包 SHA-256；未审批的发布一律拒绝导出。

另有「审计追溯」页：所有操作组成哈希链，可检索、可校验、可追溯到某次发布用了哪套策略版本。

## 核心隐私保证（服务端强制）

| 要求 | 实现 | 自动化测试 |
|---|---|---|
| 自动识别直接标识 | 字段名关键词 + 取值校验（含身份证校验位） | `detection_recall_and_precision_are_high` |
| 自由文本内姓名/电话/地址 | 正则 + 词典 + 上下文启发式，按类型记录检出/误报 | 同上 + 页面报告 |
| 同一患者跨表跨批次假名一致 | 身份证/病案号/姓名+出生日期并查集归并；假名由类内**规范标识**派生，与批次无关 | `pseudonyms_are_stable_within_project_and_differ_across_projects`、`pseudonym_is_independent_of_batching`、`same_patient_token_across_all_tables` |
| 不同课题组假名不同 | 假名 = `HMAC-SHA256(主密钥, 课题组ID | 患者标识)` | 同上 |
| 日期患者整体平移 | 每患者一个常量偏移（按课题组派生），写回所有表与文本 | `date_shift_preserves_intervals`、`date_shift_is_project_scoped_and_batch_independent` |
| 住院天数/用药间隔不变 | 同一偏移下差值不变；质量报告单独核对 | 同上 |
| 准标识泛化至 k 匿名 | 患者级等价类；年龄/邮编/诊断/性别泛化，不达标自动升级，仍不达标则抑制小类 | `k_anonymity_is_met_or_rows_suppressed` |
| 发布前算风险、不达标禁导出 | 风险阈值判定 + 审批/导出双重拦截 | 手动验证（见下） |
| 脱敏前后统计量偏差 | 均值/中位数/标准差对比，区间量判别 | 页面「风险评估」表 |
| 每次发布留审计、可追溯策略 | 哈希链审计 + 策略快照写入发布包 | `audit_chain_detects_tampering` |

### 假名一致性的关键设计

并查集根节点取决于「这一批数据恰好带了哪些标识」，因此不能直接用根做哈希输入。
实现从每个等价类中选一个**规范标识**（身份证 > 病案号 > 姓名+出生日期）再哈希，
所以同一患者无论出现在哪些表、分几批到达，只要任一稳定标识一致，假名就一致。
跨课题组时课题组 ID 进入 HMAC 输入，因此组间假名不同且不可关联。

## 检出率与误报率

合成数据生成器在自由文本中按类型埋入标识，并记录精确字符区间作为真值；
检测结果按类型统计：

- 检出率（召回）= TP / 真值
- 准确率（精确）= TP / 检出
- 误报率 = (检出 − TP) / 检出

平台故意保留了少量难例（如无结构的「联系人 姓名」重述），使指标反映真实检测上限，
而不是对自家模板的过拟合。结构化字段另有「字段类型识别准确率」逐列核对。

## 发布包内容

```
01_patients.csv 02_inpatient.csv … 05_notes.csv   # 脱敏后数据
risk_report.json        # k、再识别/起诉风险、残留扫描、判定明细
quality_report.json     # 表级行数、数值统计量前后对比、区间量核对
policy_snapshot.json    # 本次发布实际使用的完整策略
field_decisions.json    # 每个字段的处理动作
manifest.json           # 文件清单与 sha256、策略版本、审批信息
README.txt
```

文件名使用 ASCII 角色名，具体表名与 SHA-256 见 `manifest.json`。

## 架构

```
src/main.rs      启动与演示数据初始化
src/api.rs       HTTP 路由与业务编排（登记/识别/策略/评估/审批/导出/审计/合成）
src/engine.rs    脱敏流水线：实体归并、假名、日期平移、泛化与 k、风险与质量
src/detect.rs    字段识别与自由文本抽取
src/synth.rs     合成病历与埋点真值
src/detection_eval.rs  检出率/误报率统计
src/release.rs   发布包与清单
src/db.rs        SQLite 表结构
src/audit.rs     哈希链校验
web/             控制台（无构建步骤，直接内嵌进二进制）
tests/guarantees.rs  隐私保证测试
```

## 已知限制

- 过敏保护仅覆盖检测到的标识类型；自由文本中未被规则覆盖的罕见表述仍可能残留，
  因此风险评估会把「残留高置信标识」作为独立拦截项，且导出前需人工审批。
- k 匿名以（年龄段、邮编前缀、诊断、性别）为等价类键；未纳入自由文本内容。
- 主密钥保存在 `data/keys/master.key`（权限 0600）。生产环境应改为外部密钥管理。
- 审计链只能防篡改（改动任一记录会导致后续校验失败），不防删除末尾记录；
  生产环境应把链尾哈希定期外部存证。
